# 2026-04-16 21:08:34 Try1 Strategy Implementation

本次实现按 `try1.md` 的主线，优先落地当前代码里最可能带来性能收益的三项约束：

- 让 `free-space` 真正作用到车灯前方空域
- 让高发光 Gaussian 更贴近真实表面
- 让高发光 Gaussian 保持紧凑，避免沿视线拉成长条白雾

## 修改文件

- `configs/omnire_extended_cam_lidar.yaml`
- `models/gaussians/vanilla.py`

## 具体实现

### 1. 强化 free-space 约束

配置修改：

- `trainer.losses.free_space.w: 0.02 -> 0.03`
- `trainer.losses.free_space.mask_dynamic: true -> false`
- `trainer.losses.free_space.bright_weight: 0.5 -> 0.7`

原因：

- 原配置会把动态区域整体从 free-space 中排除，这会让“相机到动态后车灯之间的空域”缺少约束。
- 对 try1 的目标来说，最重要的是压掉车灯前方空气中的伪密度，因此需要让 free-space 能覆盖动态目标前方区域。
- 同时适度提高亮区权重，让强光区域的空域占据更难通过。

### 2. 新增 emissive surface support loss

在 `VanillaGaussians.compute_reg_loss()` 中新增：

- `emissive_surface_support`

实现逻辑：

- 先用当前高发光点筛出 `light source mask`
- 对这些点计算到最近深度表面点的距离
- 对超过 `margin` 的距离部分施加惩罚

形式上等价于：

- 高发光点允许亮
- 但不允许明显脱离真实表面漂浮在空中

配置项：

- `model.Background.reg.emissive_surface_support.enabled`
- `w`
- `margin`
- `max_points`
- `max_surface_samples`

### 3. 新增 emissive cluster loss

在 `VanillaGaussians.compute_reg_loss()` 中新增：

- `emissive_cluster`

实现逻辑：

- 对高发光点集合做两两距离
- 取每个点的最近邻距离
- 如果最近邻距离超过 `target_radius`，则惩罚

作用：

- 鼓励发光高斯形成局部紧凑灯簇
- 抑制沿视线方向拉成长条、形成白雾拖尾

配置项：

- `model.Background.reg.emissive_cluster.enabled`
- `w`
- `target_radius`
- `max_points`

## 当前默认权重

- `free_space.w = 0.03`
- `free_space.mask_dynamic = false`
- `free_space.bright_weight = 0.7`
- `emissive_surface_support.w = 0.05`
- `emissive_surface_support.margin = 0.15`
- `emissive_cluster.w = 0.01`
- `emissive_cluster.target_radius = 0.25`

## 设计取舍

没有在这版里直接做的内容：

- 完整的实例级车灯表面绑定
- 时序一致性损失
- specular / diffuse / emission 的更细分监督

原因：

- 这些模块理论上合理，但改动范围更大，且需要更明确的实例/语义对齐数据。
- 当前版本优先把 try1 中最核心、最可落地、最可能改善白雾的约束加进去。

## 预期效果

- 车灯前方空域的伪高斯更难存活
- 高发光点更倾向贴附在表面附近
- 发光点不容易沿相机视线拖出白雾条带

## 风险

- `mask_dynamic=false` 后，若深度或伪深度质量差，可能会对动态车辆边缘产生过约束
- `emissive_surface_support` 过强会把真实 bloom 一起压掉
- `emissive_cluster` 过强会让左右灯簇有“并拢”倾向，因此当前权重保持较小
