# LightSource Core Coverage Strategy

Time: 2026-04-20 13:41:26

## Background

The previous `light_source_branch_plan` run was stable but did not produce a meaningful image-quality gain.

Observed metrics:

- Current run full PSNR / SSIM / LPIPS: `28.2477 / 0.8345 / 0.2750`
- Close baseline `20260416..._210834`: `28.2433 / 0.8347 / 0.2745`
- Stronger baseline `20260416..._170317`: `28.6527 / 0.8416 / 0.2661`

Visual issue:

- LightSource branch was constrained, but it did not clearly improve rendering.
- Lamp and tail-light regions became soft and dirty.
- Red vertical flare was preserved but diffused into haze.
- Dynamic bright vehicles still caused ghosting.
- Depth and geometry around bright/distant regions remained noisy.

Main diagnosis:

- `coverage_w` was `0.0`, so the LightSource branch was mostly discouraged from leaking outside masks, but was not explicitly required to explain true light cores.
- A naive coverage mask would be risky because it could push LightSource to explain large flare, reflection, and dynamic ghost regions.

## Strategy

Use a two-level light mask:

- A broad mask for non-light suppression.
- A stricter core mask for coverage and color supervision.

Delay LightSource supervision until geometry has stabilized:

- Enable coverage after step `1500`.
- Ramp coverage over `2500` steps.
- Enable color supervision after step `2500`.
- Ramp color supervision over `2500` steps.

Keep LightSource compact:

- Lower max scale and max opacity.
- Lower initial intensity.
- Strengthen scale and opacity regularization.

Exclude dynamic regions from the strict coverage mask, so moving vehicle highlights and ghosted bright streaks are not treated as static light sources.

Added scheduled loss weights:

```python
def _scheduled_loss_weight(self, cfg, key: str, default: float) -> float:
    weight = float(cfg.get(key, default))
    start_iter = int(cfg.get(f"{key}_start_iter", cfg.get("start_iter", 0)))
    ramp_iters = int(cfg.get(f"{key}_ramp_iters", cfg.get("ramp_iters", 0)))
    if self.step < start_iter:
        return 0.0
    if ramp_iters > 0:
        progress = min(1.0, max(0.0, float(self.step - start_iter) / float(ramp_iters)))
        weight *= progress
    return weight
```

Changed LightSource coverage to use the strict `coverage` sub-mask when enabled:

```python
coverage_w = self._scheduled_loss_weight(light_cfg, "coverage_w", 0.0)
if coverage_w > 0:
    coverage_cfg = light_cfg.get("coverage", light_cfg)
    coverage_mask = self._compute_light_source_mask_from_pixels(
        image_infos=image_infos,
        cfg=coverage_cfg,
        valid_mask=valid_loss_mask * non_road_mask.float(),
    )
    if coverage_mask.sum().item() == 0:
        coverage_mask = light_mask
else:
    coverage_mask = light_mask
```

Added local LightSource color supervision on the strict coverage mask:

```python
color_w = self._scheduled_loss_weight(light_cfg, "color_w", 0.0)
if color_w > 0 and "LightSource_rgb" in outputs and coverage_mask.sum().item() > 0:
    light_rgb = outputs["LightSource_rgb"]
    target_rgb = image_infos["pixels"]
    light_err = torch.abs(light_rgb - target_rgb).mean(dim=-1)
    loss_dict["light_source_color"] = color_w * (light_err * coverage_mask).sum() / (coverage_mask.sum() + 1e-6)
```

## Expected Effect

Expected improvements:

- Light cores should be sharper and less fog-like.
- LightSource should no longer be only a passive non-mask regularizer.
- Dynamic vehicle highlights should be less likely to become static light sources.
- Red/yellow/white lamp cores should be more explicitly represented by the LightSource branch.

Expected risks:

- If `coverage_w` is too high, LightSource may create extra bright blobs.
- If the strict coverage mask is too narrow, the branch may still remain underused.
- If `color_w` is too high, LightSource may overfit pixel color and hurt general geometry.
