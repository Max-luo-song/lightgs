# 2026-04-22 11:49:11 Saturation-Aware Strategy Implementation

## 策略结论

本次按 `markdown/2026-0422-policy-11dian.md` 的新版策略实现：

- 不再对强光/发光体做独立 `LightSource` 分支建模。
- 过饱和像素不再作为普通可信观测强驱动 photometric loss。
- 强光亮度仍允许由普通 Background Gaussian 的 PBR / specular / emissive 表达承担。
- 高 emissive 点继续受表面几何约束，语义改为 `emissive_surface_geometry`，不再作为独立发光体类别。
- free-space、highlight geometry suppression、surface-guided densification、floater pruning 继续作为结构闭环约束。

## 代码修改

### 1. 删除独立 LightSource 分支

- 删除文件：`models/gaussians/light_source.py`
- 删除导出：`models/gaussians/__init__.py`
- 删除类型枚举：`models/trainers/base.py` 中的 `GSModelType.LightSource`
- 删除创建/初始化/单独渲染逻辑：`models/trainers/scene_graph.py`
- 删除专用监督：
  - `light_source_non_mask_opacity`
  - `light_source_mask_coverage`
  - `light_source_color`

这样训练不再要求某个独立分支去覆盖强光 mask，也不再把过饱和/flare/动态反射强行解释成静态发光体。

### 2. 新增 saturation-aware photometric reweight

在 `models/trainers/base.py` 新增 `_compute_saturation_confidence()`，用过饱和风险生成 RGB loss confidence：

- `high_luma`：亮度超过阈值的程度
- `channel_clipping`：RGB 三通道同时接近上限的程度
- `flatness`：高亮区域局部梯度过平坦时增加风险
- `confidence = exp(-sat_score)`

`rgb_loss` 优先读取：

```yaml
trainer.losses.rgb.saturation_aware_reweight
```

启用后，高亮且疑似 clipped 的像素会降低 photometric 权重，从源头减少“白斑误差 -> 几何/opacity 补偿 -> 空气雾状高斯”的路径。

### 3. 保留普通高斯的表面发射能力

`models/gaussians/vanilla.py` 中把原来容易产生歧义的 `light_source_geometry` 改为：

```yaml
emissive_surface_geometry
```

其职责是约束普通 Background Gaussian 中高 emissive 点：

- 高 emissive 点禁止 duplicate 扩散；
- 高 emissive 点 scale 做上限裁剪；
- 仍配合 `emissive_surface_support` / `emissive_cluster` 正则。

这不是独立建模发光体，而是“普通高斯允许表达亮度，但必须贴近表面或稳定壳层”。

### 4. 配置修改

`configs/omnire_extended_cam_lidar.yaml`：

- 新增 `trainer.losses.rgb.saturation_aware_reweight`
- 关闭旧的简单亮区降权 `bright_region_reweight.enabled: false`
- 删除 `trainer.losses.light_source`
- 删除 `model.LightSource`
- 将 Background 控制项改名为 `emissive_surface_geometry`

`configs/night_pbr_anti_floater.yaml`：

- 更新注释，去掉 explicit light source modeling 的表述。
