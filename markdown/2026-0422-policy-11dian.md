# 模块 A：Saturation-aware Photometric Reweighting

这是第一优先级，必须最先改。

## A1. 不再直接用亮度做 confidence

你前面说过一个直觉版：

```python
confidence = 1 - normalized_luma
```

这个方向对，但太粗，会把真实亮表面也一起打掉。

我建议你用**过饱和风险**而不是单纯亮度。

### 定义一个 `sat_risk`

基于以下几个量组合：

* 像素亮度高
* RGB 三通道同时接近上限
* 局部梯度异常平坦（大片白糊）
* 多视角不一致
* 位于已知强发光候选区域附近

可写成类似：

```python
sat_score = w1 * high_luma + w2 * channel_clipping + w3 * flatness + w4 * mv_inconsistency
conf = exp(-sat_score)
```

这里的重点是：

* **亮但有纹理、有边界**，不要太低置信
* **白且糊且跨视角不稳定**，才大幅降权

## A2. Photometric 分两路

不要一个统一 RGB loss。

### 路 1：可信区域

正常 photometric：

```python
L_rgb_clean = conf * |I_pred - I_gt|
```

### 路 2：疑似过饱和区域

不要要求精确重建 RGB，而改成**弱约束**，例如：

* 只约束色相/色温大致合理
* 或只要求达到一定亮度下限，而不是逐像素贴合
* 或直接用 robust loss + 很小权重

例如：

```python
L_sat = (1-conf) * robust_highlight_loss(I_pred, I_gt)
```

这样做的效果是：

> 强光区域不再要求“逐像素白斑精确拟合”，自然也就不会疯狂逼几何去填误差。

这是你之前几版最缺的地方。
因为前面的方案大多在控高斯，但没有先控“错误观测权重”。

# 模块 B：表面辐射承担亮度，几何只负责贴表面

这是第二优先级。

你之前已经尝试了 anisotropic emissive、cone prior、light-source geometry decoupling，这个方向我认为是对的。
但我会把它再推进一步，变成**职责硬分工**。

## B1. 发光高斯必须“近表面存在”

不是直接全局学 emissive，而是限制：

> 高 emissive 的 Gaussian，必须位于真实表面附近，或至少位于稳定可见壳层附近。

这个你之前的 `emissive_surface_support` 已经在做雏形。
但我建议把它从“一个额外 regularization”提升成**发光高斯合法性条件**。

### 做法

对高 emissive 高斯计算 support score：

* 到最近表面点距离
* 多视角可见一致性
* 是否处于稳定高亮边缘附近

如果 support 差：

* 不是简单加点 loss
* 而是直接降低它的 emissive 更新权重，或标记为非法发光体候选

也就是说：

```text
发光不是人人都能学
只有“贴近表面且多视角稳定”的高斯，才有资格承担发射亮度
```

## B2. 发射增强，几何解释受限

在强高亮区域内，优化时要让：

* emissive 参数更容易响应
* opacity / scale 更难通过增加来降 loss

可以理解为“梯度配额重分配”。

### 具体体现

对于高亮候选点：

* 降低 opacity 的 learning rate 或梯度系数
* 降低 scale 扩张速度
* 提高 emissive 参数更新敏感度
* duplicate 禁止，split 仅允许贴表面 refinement

你之前的 `dup_block`、`max_scale`、方向性 emissive 是对的，但还不够系统。
我这里要的是：

> **高亮解释时，几何不能和发射平权竞争。**

## B3. 发光必须方向合理

这个保留你之前的思路：

* 低阶 SH emissive
* cone prior
* back-energy regularization。 

但我会把它定义成目的更明确的一条：

> 不是为了“让灯更真实”，而是为了让优化器有一条比空气补偿更便宜的亮度解释路径。

# 模块 C：自由空间必须成为“不可居住区”

这层才是你之前已经做了很多的 anti-fog 结构层，但我会重新组织。

---

## C1. 自由空间判定不要只依赖深度

因为你自己已经说了伪深度不稳，所以不能全押深度。

自由空间评分 `free_space_score` 应来自三部分：

### 1. 深度前方约束

如果已知表面深度，则表面前方一段距离默认是 free space。

### 2. 多视角不一致

某 Gaussian 在不同相机下贡献忽隐忽现、位置不稳定，则更像空气补丁。

### 3. 贡献-可见性失衡

如果某点经常被看见，但只在少数强光帧里贡献亮度，说明它不像真实表面，更像“误差修补点”。

这样你就不用死依赖一条伪深度。

---

## C2. 自由空间中的高斯直接分三类处理

不要所有 floater 都一个策略。

### 类 1：新生种子

还没形成结构，只是刚被 densify 出来。

处理：**直接阻断出生**

* split block
* dup block
* refine budget = 0

这部分你前面其实做了很多。 

### 类 2：半透明补丁

opacity 低，scale 大，沿视线拖尾。

处理：**快速饿死**

* transmittance penalty
* fog penalty = opacity × scale × free_space_score
* 降低其 photometric 解释收益

### 类 3：顽固残留点

已参与多轮训练，删不掉但又不贴表面。

处理：**强清理**

* hard prune priority 提升
* 如果长期 support score 低，则直接 prune
* 不再保护“高梯度但低支持”的点

这一点很重要。
因为很多顽固雾点正是“梯度高”，所以普通 prune 会误以为它很重要。

---

## C3. Transmittance 不是辅助项，而是空气合法性约束

你前面也做过 free-space / rear pseudo / bright weight 增强。 
但我建议再明确一点：

### 原则

```text
如果一条 ray 在表面前方被吸光，那就是非法
```

### 损失形式

比起单纯 `1 - T_end`，更建议做**分段 transmittance**：

* 表面前：要求高透明
* 表面附近：允许变化
* 表面后：不严格约束

这样对真实灯壳附近的局部体积更宽容，对空气更严格。

# 模块 D：densification 不再按“梯度大就长”，而按“可信梯度”长

这是整个工程里第二关键的地方。

你前面的很多 gate 已经在控 split/dup，但我现在给一个更底层的原则：

## D1. 定义 `trusted_grad`

不是用原始 grad，而是：

```python
trusted_grad = grad * conf * support_score * (1 - free_space_score)
```

只有 trusted_grad 高，才允许 densify。

这比“亮区低 opacity 不增长”“free-space dup_keep_ratio=0”更本质，
因为它直接改变了 densify 的依据，而不是只在候选生成后筛掉。
你前面的门控很多是在候选生成之后拦截。
我这里要做的是：

> **让错误梯度从一开始就拿不到增殖资格。**

## D2. split 和 dup 区分职责

### split

只服务于贴表面细化、边界重建。

### dup

只服务于已确认稳定表面的局部密度补充。

强光候选区域：

* 允许 surface-aligned split
* 禁止 free-space dup
* 禁止沿 view ray 扩散式复制

这跟你 `light_source_geometry.dup_block` 很接近，但我会扩展到所有高风险高亮点，而不仅仅是高 emissive 点。
